= Operated by conversation
:page-type: concept

_Why the assistant is part of the platform, not a tool you point at it._

You open code-server and Claude Code is already there. The platform installed
it, with thinkube-control's own API in reach: every operation the control panel
can perform is exposed to it as MCP tools. There is nothing to configure.

That is a different claim from "an MCP server is available." The assistant is
provisioned as part of the platform, with the platform's state and the
platform's documentation already reachable. You ask for things in your editor,
in your own words, and the tools do them.

== What it reads and what it changes

The operations are split on purpose. Reading — the list of services, a pod's
description, its logs, the health history, what's on each GPU — is exposed as
*resources* the assistant may consult as context. Changing — deploying a
template, loading a model, restarting a service — is exposed as *tools* it
uses only when you ask.

So "why is JupyterHub down?" is answered by reading, and fixed by asking.
Nothing changes because the assistant thought it should.

== The same surface as the control panel

thinkube-control's web UI and its MCP endpoint are the same application.
There is no second implementation to drift. Anything the assistant does, you
can do by clicking; anything you can click, the assistant can be asked for.

== When Kubernetes surfaces

It will. This is an alpha, and things break. When they do, the assistant has
the pod state, the container logs and the service history through the same
resources, and it knows what those mean. You are not the one reading `kubectl`
documentation at eleven at night; you are the one asking what happened.

== What this needs

Claude Code is a paid service from Anthropic, and it is a real dependency for
the development half of Thinkube — describing what you want and having it
built. The platform itself runs without it: models serve, applications run,
thinkube-control manages the cluster, and none of that reaches outside your
machine.

Describing and building needs a frontier model today. A model served on your
own GPU can power your applications; it does not drive their development.

== The documentation is reachable the same way

The documentation site deploys inside your cluster as well as on the web, and
the assistant can search it. Ask where something is documented and the answer
comes from the pages, not from recall — and it works with no internet
connection.
