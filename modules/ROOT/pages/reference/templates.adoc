= Templates catalog
:page-type: reference

_Every template in the platform catalogue, what it deploys, and what it needs._

A template is a repository with a `thinkube.yaml` and a Copier configuration. Deploying one gives you a running application and a git repository you own in Thinkube Git. The catalogue is `repositories.json` in `thinkube-metadata`; entries of type `application_template` are what *Templates* in thinkube-control lists. Each entry's `deployment_type` comes from its descriptor: *app* is always on, *knative* scales to zero, *component* has a fixed name and its pods are created by the LLM Gateway when a model is loaded.

image::cp-templates.png[The Templates page of thinkube-control]

[cols="2,1,1,3",options="header"]
|===
| Template | Type | GPU | Deploys

| `tkt-webapp-react-fastapi` | app | — | A web application: React frontend on thinkube-style, FastAPI backend, PostgreSQL, sign-in through Thinkube Identity, tests and migrations wired. The xref:webapp-template:index.adoc[template pages] are written from it.
| `tkt-vllm-gradio` | component | yes | The vLLM inference server the LLM Gateway drives, with a Gradio chat interface
| `tkt-tensorrt-llm-harmony` | component | yes | The TensorRT-LLM inference server the LLM Gateway drives, for NVFP4 models on Blackwell
| `tkt-text-embeddings` | component | yes | The Text Embeddings Inference server the LLM Gateway drives, for embedding models registered in Thinkube Experiments
| `tkt-stable-diffusion` | app | yes | Stable Diffusion image generation; asks for the model id at deploy time
| `tkt-seaweedfs` | app | — | A file gateway over Thinkube Storage: a REST API and an upload page
| `tkt-knative-demo` | knative | — | A minimal scale-to-zero service, for checking a Knative deployment
| `thinkube-style` | app | — | The component showcase of the thinkube-style design system
| `thinkube.org` | app | — | This documentation site, deployed inside the cluster so Claude Code can search it
|===

The three *component* templates are also the entries of the optional-components catalogue named `vllm`, `tensorrt` and `text-embeddings`. Installing the component deploys the template; loading a model creates its pods.

Deploy one from thinkube-control under *Templates*, by name or from a GitHub URL, or ask Claude Code: `deploy the web app template, call it notes`. xref:webapp-template:deploy.adoc[Deploy a template] follows one deployment step by step, and xref:webapp-template:create-a-template.adoc[Turn your app into a template] shows how an application you built becomes an entry in your own catalogue.
