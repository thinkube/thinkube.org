= Build a research assistant over your own papers
:page-type: tutorial

_Check the platform's services from a notebook, load a chat model and an embedding model, index a corpus of papers in Qdrant, ask it questions with sources, then have two agents argue from the index and a third judge them. Four notebooks, run in order; what each one showed on the reference cluster._

The four notebooks are under `thinkube/notebooks/examples/research-assistant/` in Thinkube Notebooks. Each leaves something the next one uses, so the platform is assembled rather than demonstrated: services, then models, then retrieval, then agents. There is no training here.

.What you need
* Thinkube Notebooks with the `agent-dev` kernel. A node without a GPU is enough; the models run behind the LLM Gateway, not in the notebook.
* The vLLM and text-embeddings backends installed from *Optional Components*, and a chat model and an embedding model mirrored. The run below used `Qwen/Qwen3.5-4B` and `Qwen/Qwen3-Embedding-0.6B`.
* For notebooks `02` and `03`: the optional components Qdrant and Langfuse, and outbound access to arXiv. Langfuse needs ClickHouse and Valkey, which *Optional Components* lists as its requirements.
* For notebook `03`: a chat model the catalogue marks for tool use, served with a tool-call parser that matches the model's call format. Section 4 says what happened on the reference cluster without one.
* For the caching and messaging cells of `00`: Valkey and NATS.

Notebook `00` runs with whatever is present and says what is missing, so run it first even when you are confident.

== 1. Check the services are there

Open `00-platform-validation.ipynb` with the `agent-dev` kernel and run all cells. It tries seven services in turn: the LLM Gateway, Qdrant, Langfuse, Thinkube Experiments, PostgreSQL, Valkey and NATS. Each cell prints a green line for a service it reached, a grey line for one it is not configured for, and a red line for one that answered with an error.

On the reference cluster, run before the optional components were installed, it showed:

* *LLM Gateway*: connected; chat model `Qwen/Qwen3.5-4B` and embedding model `Qwen/Qwen3-Embedding-0.6B` loaded; the two GPU nodes with 3 of 4 slots free each. Then a red line: `'NoneType' object has no attribute 'strip'`. The chat test asks for one word with `max_tokens=20`. Qwen3.5 is a reasoning model and spends its budget thinking, so the visible answer came back empty. Notebook `01` makes the same call with `max_tokens=1024` and explains the budget; `02` and `03` switch thinking off. The red line is the cell reporting a real limit, not a broken gateway.
* *Qdrant*: `404 (Not Found)`, because Qdrant was not installed yet.
* *Langfuse*: not configured, because it was not installed yet.
* *Thinkube Experiments*: connected; the cell created the `research-assistant-validation` experiment and a run named `platform-test`, and printed the link to it.
* *PostgreSQL*: connected, PostgreSQL 18.6.
* *Valkey*: connection reset, because it was not installed yet.
* *NATS*: connected; the pub/sub test received its own message.

Install the missing components and run the notebook again; the grey and red lines turn green.

== 2. Load the models you will use

`01-register-litellm.ipynb` is about model management: what the registry holds, what your GPUs have room for, and how a model goes from `deployable` to `loading` to `available`. It uses `tk_llm`, the platform's Python client:

[source,python]
----
from tk_llm import LLMClient, get_openai_client

llm = LLMClient()
llm.list_models()                     # registry and state
llm.gpu_status()                      # nodes, slots, memory
llm.load_model("<model>", node="<node>", max_context_length=32768)
----

== 3. Index a corpus and ask it questions

`02-langchain-rag.ipynb` builds the retrieval pipeline over the 2025–2026 literature on reasoning post-training: fetch papers from arXiv, chunk them, embed the chunks through the gateway, store them in Qdrant with a payload you can filter on, and wire a chain that answers from what it retrieved, with Langfuse tracing every query.

What follows is the run on the reference cluster, with Qdrant, Langfuse and their requirements installed from *Optional Components*, and `FETCH_FULL_TEXT` left at its default of off.

*Fetch.* Three anchor papers are fetched by identifier, because keyword search cannot reach a field's founding paper, then three keyword searches of 50 results each, one per side of the debate plus background. The run fetched DeepSeekMath, DeepSeek-R1 and _Does Reinforcement Learning Really Incentivize Reasoning Capacity_ as anchors, 50 GRPO papers, 50 distillation papers and 43 general reasoning papers after deduplication: 146 papers, 215 thousand characters of abstract. With `FETCH_FULL_TEXT = False` only abstracts are indexed; arXiv's metadata is public domain. Switching it on downloads each paper's LaTeX source, which carries its own licence, and extracts algorithms, results tables, equations and the setup and limitations prose. The notebook says why that is a decision to make knowingly. Fetching is rate-limited to one request per three seconds, as arXiv asks.

*Let the corpus name its foundations.* With full text fetched, the bibliographies are read, the most-cited works missing from the corpus are fetched by identifier, and they join as anchors. On this run the cell printed *No references parsed — set FETCH_FULL_TEXT = True and re-run the fetch cell*, because there were no bibliographies to read. The notebook's own earlier full-text run had DeepSeekMath, DeepSeek-R1 and PPO at the top of that ranking: the paper that introduced GRPO, the model that made it famous, and the algorithm it modifies.

*Chunk.* Pieces of about 1,000 characters with 200 of overlap, tagged with their content type. The run produced 431 chunks, all of them abstracts, three per paper on average. With full text the corpus is mostly numbers unless results and equation chunks are capped per paper, which the notebook does.

*Embed.* Batches of 32, because Text Embeddings Inference rejects a larger batch with a bare 422 that reaches the notebook as a 503 from the gateway. Items can come back out of order and are re-sorted by index. The run embedded all 431 chunks with `Qwen/Qwen3-Embedding-0.6B` at 1,024 dimensions and sent one embedding trace to Langfuse.

*Store.* A Qdrant collection with the embedding's dimension and cosine distance, uploaded in batches of 500 because a single request is capped at 32 MB. The run deleted and recreated `rl_reasoning_papers` at `qdrant.<your domain>` and uploaded the 431 vectors in one batch, each carrying the plain text, the raw text, its content type and the side of the debate it belongs to.

*Ask.* Two settings decide whether the chain works at all, and both were found by reading answers rather than exit codes. `check_embedding_ctx_length=False`, because LangChain otherwise pre-tokenises the query with OpenAI's tokenizer and sends integers, which a non-OpenAI embedding server embeds as if they were words; measured on this notebook, the query vector's similarity to the same sentence sent as text was 0.30 with the default and 1.0 with the flag. And `enable_thinking: False`, because a reasoning model's thinking is billed against `max_tokens` and leaves nothing for the answer. The retriever reserves four prose chunks and two evidence chunks per question, so a conceptual question is answered with an argument rather than a benchmark grid.

The run asked its three questions of `Qwen/Qwen3.5-4B` and each came back with an answer and four cited sources. Asked what GRPO is and how it differs from PPO, the model answered that GRPO drops the value network and compares a group of candidates the model generated itself, citing the GRPO-SG, CoDistill-GRPO and GRPO-VPS papers. Asked whether verifiable-reward training creates new reasoning ability or sharpens what the base model has, it answered *primarily a sharpening mechanism*, citing among others the anchor paper that asks that question. Asked when distilling a teacher's traces beats running reinforcement learning on a small model, it answered that curated traces win on sample efficiency, citing NaturalThoughts and RLKD. Each answer is only as good as the abstracts under it; the point of the cell is that you can see which ones.

*Trace.* Langfuse's callback records each retrieval and each generation. The run's trace cell fetched 8 traces, left out 2 that were newer than its 30 second ingestion window because their latency was not final yet, and summarised the 6 that remained: 4 retrieval-and-answer and 2 embedding runs. It plots latency per trace type, because pooling the two produces a mean that describes neither, and says so under the chart.

The last cell lists the 146 indexed papers with their identifiers and dates, so you can see what your assistant knows.

== 4. Put the index to work in an argument

`03-multi-agent.ipynb` reads the collection `02` built and hands it to three AG2 agents. Two advocates argue opposite sides of a question the literature has not settled: whether to post-train a small model with reinforcement learning on verifiable rewards or by distilling a larger model's reasoning traces. Each can only cite what `search_papers` returns from your index. A judge scores both on five equally weighted criteria, declares a winner, and calls `generate_code`, which retrieves algorithm chunks for the winning approach and writes an implementation grounded in them, checked for completeness and syntax but never run.

The notebook prefers a model whose serving stack advertises tool support, because the agents cannot cite anything unless the model can emit a well-formed call. Every advocate prompt says *search once, then argue* and ends every turn with a marker, because without the first an agent keeps searching and without the second the proxy cannot tell the turn is over. Thinking is switched off in three places for the same reason as in `02`.

Rebuttals are what make it a debate rather than two monologues: each side reads the other's opening and answers it. Re-run it with a different seed, or after adding papers. A verdict that flips is telling you the evidence is thin, which is itself worth knowing.

*What the run on the reference cluster showed.* The notebook was run twice.

With `Qwen/Qwen3.5-4B`, the only chat model loaded, the first advocate's turn failed at the gateway: `"auto" tool choice requires --enable-auto-tool-choice and --tool-call-parser to be set`. The vLLM server adds those flags only for models the catalogue marks for tool use, and Qwen3.5-4B is not one of them. That is the notebook's own warning made concrete: without tool calling there is no debate.

`Qwen/Qwen3-8B` is the smallest vLLM model the catalogue marks for tool use. Mirrored and loaded, it replaced Qwen3.5-4B on the backend, and its server started with `--enable-auto-tool-choice --tool-call-parser qwen3_coder`. The notebook picked it, connected to the collection, found the 431 vectors and 146 papers, and ran its own check of `search_papers`, which returned four papers. Then the debate ran to the end without a single search reaching the index. Each advocate answered its prompt with the text of a call, `<tool_call>{"name": "search_papers", …}</tool_call>`, the moderator returned an empty turn, and the advocate sent the same call again until its turn limit. The judge did the same with four calls at once. The results cell reports four arguments of between 123 and 150 characters, all of them unparsed calls, and *Code generation returned empty*.

The cause is on the serving side, and the server's own source says where: it maps the `qwen3` reasoning format to vLLM's `qwen3_coder` parser, which reads the XML call format, and notes that a Qwen3 model that emits JSON calls in the Hermes style needs `TOOL_CALL_PARSER=hermes` set for it. Qwen3-8B emits the Hermes style, and the catalogue entry does not set the override. Until it does, this notebook on this cluster produces the transcript above. The record is honest about it: xref:contributing/gaps.adoc[Known gaps] lists it.

== What you have now

A retrieval assistant over a corpus you chose, running on your own hardware: your models, your vector store, your traces. Swap arXiv for your own documents and the same four steps hold, with Qdrant, the gateway and Langfuse unchanged.

If the debate leaves you wanting to run the winner rather than read about it, xref:playbooks/zebra-grpo.adoc[Fine-tune on verifiable rewards] trains a model with reinforcement learning on rewards a program checks and serves it through the same gateway.
