== Overview

=== Basic idea

A Knative service holds no pods while nobody calls it. The first request starts one, a burst of requests starts more, and when the requests stop the service returns to no pods. It suits what you call now and then: a webhook, a small API, a tool for one person. On a DGX Spark the memory an idle pod would hold is also GPU memory, so it stays free for models.

* *Scale to zero.* An idle service costs no memory and no CPU.
* *Scale on load.* Knative adds a pod each time the running pods are full, up to the limit you set.
* *Same pipeline as every app.* The service is a repository in Thinkube Git, built by the platform and deployed at its own address under your domain.

=== What you'll accomplish

You deploy `knative-demo` from the Knative demo template, call it from zero pods, send a burst of requests that starts more pods, and watch it return to zero.

=== Supported hardware

[cols="1,1,1,2",options="header"]
|===
| Node | Architecture | GPU | On the reference run

| tkamd1 | amd64 | none | control plane
| tkamd2 | amd64 | 2 × RTX 3090 | the Knative gateway
| tkspark | arm64 | GB10 | the service's pods
|===

The template's image is built for amd64 and arm64, so its pods run on any node. It needs no GPU.

=== Time & risk

* *Estimated time:* 5 min. The deploy took 97 and 108 seconds on two runs, a pushed change was live 93 seconds after the push, and the calls take seconds.
* *Risk level:* Low. The service lives in its own namespace, `knative-demo`, and changes nothing else.
* *Rollback:* Deploy the template again. A deploy of the same name overwrites the service; nothing is lost that you need.
* *Last updated:* 2026-09-16. Measured on two deploys, one scaling run and one pushed change.

== Instructions

=== Step 1. Deploy the template

The template is a complete service: a small HTTP server, its `thinkube.yaml` with the scaling settings, and its tests. Deploying it creates your own repository and builds and deploys the service.

Ask Claude:

----
› make a service called knative-demo from the Knative demo template
----

Claude calls `deploy_template` with `https://github.com/thinkube/tkt-knative-demo` and follows `get_deployment_status` until it reports `success`.

Or by hand: in thinkube-control open *Templates*, choose *tkt-knative-demo*, name it `knative-demo` and deploy.

Expected output:

----
status: success
output: Deployment completed successfully
duration: 97.4
----

=== Step 2. Read the scaling settings

The settings live in the repository, in `thinkube.yaml`, so changing them is a commit.

Ask Claude:

----
› show me the deployment settings in knative-demo's thinkube.yaml
----

Expected output:

[source,yaml]
----
spec:
  deployment:
    type: knative
    minScale: 0
    maxScale: 3
    containerConcurrency: 5
    timeoutSeconds: 30
----

`minScale: 0` lets the service go to no pods. `containerConcurrency: 5` is how many requests one pod takes before Knative starts another. `maxScale: 3` caps the pods.

=== Step 3. Call it from zero pods

When nothing has called the service for a while, it has no pods. The first request starts one and waits for it.

Ask Claude:

----
› how many pods does knative-demo have? then call it and time the call
----

Expected output, from the reference run:

----
pods: 0
first request from zero: 1.52 s, HTTP 200
{
  "message": "Hello from Knative!",
  "app": "knative-demo",
  "simulated_work_ms": 100,
  "hostname": "knative-demo-00002-deployment-6bb6bd7d8c-lc85b"
}
warm request: 0.13 s
----

The service answers at `https://knative-demo.<your domain>/`. Besides `/`, it answers `/health` with its uptime and request count, and `/scale-test` with the same simulated work.

=== Step 4. Send a burst and watch it scale

Thirty requests at once are more than one pod takes, so Knative starts more pods, up to three.

Ask Claude:

----
› send 30 requests at once to knative-demo's /scale-test and list its pods
----

Expected output:

----
knative-demo-00002-deployment-6bb6bd7d8c-lc85b   2/2   Running   7s
knative-demo-00002-deployment-6bb6bd7d8c-q7h2x   1/2   Running   3s
knative-demo-00002-deployment-6bb6bd7d8c-wcjvb   1/2   Running   3s
----

*Knative Services* in thinkube-control shows each service with its pod range, its requests per pod and its timeout:

image::cp-knative-services.png[The Knative Services page of thinkube-control, with knative-demo active and its limits: 0 to 3 pods, 5 requests per pod, 30 second timeout]

=== Step 5. Watch it return to zero

With no requests, Knative removes the pods again.

Ask Claude:

----
› tell me when knative-demo is back to zero pods
----

Expected output: on the reference run the service had no pods 71 seconds after the last request.

=== Step 6. Change the greeting and ship it

The template's two settings are variables in `thinkube.yaml`: `GREETING`, the message, and `SIMULATE_WORK_MS`, the work each request pretends to do. A push builds and deploys, as for any app.

Ask Claude:

----
› in apps/knative-demo set the GREETING default to "Hello from my cluster", commit and push, then call it when the deploy is done
----

Expected output: 93 seconds after the push, the call answers with `"message": "Hello from my cluster"` from a new revision, `knative-demo-00003`.

== Troubleshooting

[cols="1,1,2",options="header"]
|===
| Symptom | Cause | Fix

| The first call takes over a second; the next ones take a tenth of that
| The service had no pods, and the call waited for one to start
| Expected. Set `minScale: 1` in `thinkube.yaml` if the first call must be fast; the service then keeps one pod.

| Pods show `1/2 Running` while a burst is served
| New pods are starting; requests queue until they are ready
| Expected. Wait for `2/2`.

| `git push` is rejected with `! [rejected] main -> main (non-fast-forward)`
| After every deploy the build pipeline commits the new image tag to the repository, so your checkout is one commit behind
| Run `git pull --rebase`, then `git push` again.

| A call to another path answers `{"error": "not found"}` with HTTP 404
| The demo answers only `/`, `/health` and `/scale-test`
| Call one of those three paths.
|===
