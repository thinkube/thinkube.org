= What Thinkube is
:page-type: concept
:page-aliases: why/index.adoc, how-it-works/architecture.adoc, how-it-works/kubernetes-underneath.adoc, how-it-works/mcp-operation-model.adoc, apps/claude-code.adoc

Thinkube is a platform for one developer, on machines you own, that takes an AI project from an idea to a running product: a model served on your GPU, an app that calls it, notebooks to fine-tune it, and a report on every change. You operate it by talking to Claude Code.

Open Thinkube IDE in your browser, start Claude Code, and say what you want: _"get Qwen3.5-4B and serve it"_, _"make an app called notes from the web app template"_, _"install Qdrant"_. Each sentence is a real operation of the platform, and the same click in thinkube-control. The xref:index.adoc#playbooks[playbooks] are those sentences, one task each, with what you get.

The areas are one platform. A dataset a notebook writes is the file an app reads, the model a notebook fine-tunes is the address the app calls, and the change Tandem delivers ships by the pipeline the app took. The base is what they share: one sign-on, one filesystem, one registry, one pipeline, one way to drive it.

== How you work with it

* *Thinkube IDE* is VS Code in the browser, with Claude Code installed and connected to the platform. This is where you say things.
* *Claude Code reads freely and changes on request.* thinkube-control offers its operations to Claude through MCP. Reading state, what is running, what the GPUs hold, a build's log, is something Claude consults whenever it needs to. Changing state, a deploy, a load, an install, a restart, happens when you ask. The line between the two is drawn in the platform, not left to Claude's judgement.
* *`thinkube.yaml`* describes an app in a few dozen lines: its containers, routes and the services it uses. The platform generates the Kubernetes objects from it, so you deploy to Kubernetes without writing Kubernetes. xref:apps/index.adoc#_thinkube_yaml_your_app_without_the_kubernetes[Thinkube GitOps] shows one.
* *thinkube-control* is the control panel: models, the LLM Gateway, templates, components, nodes, secrets, tokens. Everything Claude can do, you can click here, and the health of every service is on its card.
* *Thinkube Notebooks* is JupyterLab with two environments built for your hardware, `fine-tuning` and `agent-dev`, on the same filesystem as the IDE.
* *The LLM Gateway* is one address for every served model, `llm.<your domain>`, speaking the OpenAI and Anthropic APIs.
* *Optional components* arrive with one sentence: vector stores, tracing, search, messaging, caches, inference backends. xref:reference/components.adoc[The components catalog] lists them.

== What comes out

What you build is a git repository with real code, a Containerfile, tests and a standard image. Under it is unmodified upstream Kubernetes, installed with kubeadm: `kubectl version` on the reference cluster reports v1.36.4 at the upstream release commit, with no vendor suffix. Your repository builds and deploys on any cluster that standard runs on.

== Why it is built this way

* *Production is a system, so use the one that exists.* An address and a certificate, a login, a build that repeats, a rollback, a shared GPU, storage, traces: all of it exists in Kubernetes, maintained by thousands of people. Thinkube installs it unchanged, decides the base once (Keycloak, Harbor, PostgreSQL, SeaweedFS, Gitea, Argo, each chosen so it cannot be relicensed against you), and puts Claude Code on top so you operate it in sentences. Above the application it offers choices: three vector stores, four inference backends.
* *A model you own beats a model you rent.* Small open models are good enough for most production tasks, and a fine-tuned small model beats a frontier model on the narrow task it was tuned for. The weights on your disk are the same weights tomorrow, nothing you send them leaves your machines, and once the GPU is bought every experiment is free. One gateway serves any of them behind the same API, so the app stays the same when the model changes.
* *Your data becomes capability.* Prompting has a ceiling. Fine-tuning encodes your format, vocabulary, tools and tone, and the long prompt goes away with its cost and latency. Your traces, documents and checkers are what nobody else has: a program that can verify an answer can train a model with no labelled data, and today's traces are tomorrow's training set. The result goes behind the same address, is compared with yesterday's, and is kept or rolled back.
* *One person.* One GPU serves one developer without a scheduler or a queue. One login, one set of credentials, one machine. A lab shares it the way lab equipment is shared: by saying who has the GPU this afternoon.

== Where it runs

Ubuntu 24.04 on one to a few machines. Thinkube runs on a DGX Spark (GB10, arm64) and on x86-64 workstations with RTX 3090s, and one cluster mixes both. Thinkube is alpha software: a new version may need a fresh install, so install it on a machine you can reinstall. Claude Code is a paid service from Anthropic and part of the platform.
