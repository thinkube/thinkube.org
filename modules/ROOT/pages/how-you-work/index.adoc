= The cockpit
:page-type: concept

_The three places you work, what each is for, and how to choose between them._

Thinkube gives you three surfaces. They share one workspace on one filesystem, so a file you edit in one is the same file in the others. Which one you open depends on what you are doing, not on where the file is.

== Thinkube IDE with Claude Code

Thinkube IDE is VS Code in the browser (code-server), at `ide.<your domain>`. It arrives configured: Claude Code is installed, and its MCP configuration already points at thinkube-control, so operating the platform is something you ask for from a terminal. `gh` is logged in to GitHub with the token you gave the installer, git can push to Thinkube Git, and the shell has the platform's credentials. Thinkube Tandem is installed as an extension, with its own icon in the activity bar.

image::ide-home.png[Thinkube IDE after login, with the workspace folders Apps, Components, User Templates, Platform and Tandem Board]

xref:how-you-work/claude-code.adoc[Drive Thinkube from Claude Code] shows what to ask for.

== Thinkube Notebooks

Thinkube Notebooks is JupyterHub, at `notebooks.<your domain>`. When you start a server you choose the node, the cores, the memory and the GPUs from a form that shows what each node has free. Two environments are built at install, `fine-tuning` and `agent-dev`; they appear as kernels. The example notebooks are in the workspace under `examples/`.

image::notebooks-spawn.png[The Server Options form of Thinkube Notebooks: node, CPU cores, memory and GPUs]

xref:how-you-work/ai-lab.adoc[Thinkube Notebooks] walks through it.

== thinkube-control

The browser panel at `control.<your domain>`. Everything Claude Code can do is a click here, in three groups: *Dashboard* (every service and its health), *Deployment & Infrastructure* (LLM Gateway, AI Models, Templates, Harbor Images, Optional Components, Cluster Nodes) and *Configuration & Security* (Jupyter Kernels, JupyterHub Config, Secrets, API Tokens).

image::cp-dashboard.png[thinkube-control, All Services]

xref:control:index.adoc[thinkube-control] lists every page and every operation.

== Which one, when

[cols="2,1",options="header"]
|===
| You want to | Open

| Write or change code, run Tandem, ask for anything the platform does | Thinkube IDE
| Explore data, train, evaluate, call a served model from Python | Thinkube Notebooks
| See what is running and whether it is healthy | thinkube-control, or ask Claude Code
| Mirror a model, load it, unload it | Either: ask Claude Code, or *AI Models* and *LLM Gateway*
| Deploy a template, follow a build | Either: ask Claude Code, or *Templates*
| Build a notebook environment | Either: ask Claude Code, or *Jupyter Kernels*
| Install or switch off an optional component | thinkube-control, *Optional Components* and the service's details page
| Add a node | thinkube-control, *Cluster Nodes*
|===

The rule of thumb: Thinkube IDE for anything you would say in a sentence, thinkube-control when you want to see the state of things, Thinkube Notebooks when the work is Python.

== One workspace

The three share a persistent filesystem. Edit a notebook in Thinkube Notebooks and open the same file in Thinkube IDE; deploy an application and its checkout appears under `apps/` in both. The filesystem lives on Thinkube Storage, outside the cluster, and survives a rebuild of the cluster underneath.
