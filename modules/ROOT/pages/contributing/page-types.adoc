= Page types
:page-type: reference

_Every page is one of four types, and every page of a type has the same section order. The type is declared with `:page-type:` under the title and shown as a badge._

.TL;DR
Copy the skeleton for the type below and fill it in order. Every type opens with a TL;DR that does the task through Claude Code and closes with Limits. A page that cannot follow its type's order is a different type, or two pages.

== The four types and their shape

[cols="1,2,3",options="header"]
|===
| Type | Use it for | Section order

| `tutorial`
| A start-to-finish path that ends with something working, for a reader who is learning.
| TL;DR · What you will learn · What you need · numbered steps, each "why, then how" · What you have now · Limits

| `how-to`
| A task for a reader who knows what they want.
| TL;DR · Why this is one sentence · By hand, and what is happening underneath · Limits

| `concept`
| An idea, a decision, or a mechanism, for a reader who wants to understand.
| TL;DR · The decision · What it saves you · Where it shows up · Limits

| `reference`
| Exact lookup material: fields, operations, catalogues.
| TL;DR · one section per thing, tables preferred · Limits
|===

Two rules apply to every type:

* *One type per page.* A page that teaches a concept and walks through a task is two pages that link to each other.
* *Concepts are linked, not re-explained.* A word from the xref:concepts/running-software.adoc[Concepts] pages is linked the first time a page uses it and is not defined again.
