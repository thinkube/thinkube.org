= Documentation map
:page-type: reference

_Every page of the site, where its source lives, and the type it is written as._

The site is one Antora component, `thinkube-docs`, built from five repositories. Four of them keep their pages beside the code the pages describe and join the component as named modules; the site's own pages are the ROOT module. The sidebar is one file, `modules/ROOT/nav.adoc` in `thinkube.org`, and lists every page below once.

|===
| Module | Repository | Pages

| ROOT | `thinkube/thinkube.org`, `modules/ROOT/` | Start here, Using it, Playbooks, Reference, How it works, Contributing
| `install` | `thinkube/thinkube-installer`, `docs/` | Install
| `control` | `thinkube/thinkube-control`, `docs/` | thinkube-control reference
| `tandem` | `thinkube/thinkube-tandem`, `docs/` | Thinkube Tandem
| `webapp-template` | `thinkube/tkt-webapp-react-fastapi`, `template-docs/` | Templates: the round trip
|===

== What is not documented, on purpose

The services behind the branded names — Gitea, Harbor, ArgoCD, MLflow, Keycloak, JuiceFS, SeaweedFS, PostgreSQL, DevPI, Argo Workflows — and the optional components get no pages about their own interfaces. They appear as mechanism in xref:how-it-works/components.adoc[Platform components] and as entries in the xref:reference/components.adoc[components catalog]. The documented surface is the three surfaces of xref:how-you-work/index.adoc[the cockpit] and the four stages; a new page about a service's own dashboard needs a reason this map does not yet give.

== Adding a page

. Pick the type from xref:contributing/page-types.adoc[Page types] and copy its skeleton.
. Put the file in the module whose repository holds the code it describes.
. Add one line to `nav.adoc` in `thinkube.org`. A page not in the nav is not on the site.
. Build locally with `npx --no-install antora --fetch antora-playbook.yml` in `thinkube.org`; the build must print no warnings.
. Name the source file each factual sentence was checked against in the commit message.
