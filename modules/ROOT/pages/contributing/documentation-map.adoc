== What is not on the site, on purpose

* The services behind the branded names, Gitea, Harbor, ArgoCD, MLflow, Keycloak, JuiceFS, SeaweedFS, PostgreSQL, DevPI, Argo Workflows, and the optional components get no pages about their own interfaces. They appear as mechanism in xref:how-it-works/architecture.adoc[Architecture] and as entries in the xref:reference/components.adoc[components catalog].
* The platform's own uses of `thinkube.yaml`, components and repositories the platform does not deploy, are platform development and are documented for maintainers outside the site.
* A playbook is published only from a run that completed end to end on the reference cluster. Drafts of playbooks whose processes did not complete are kept in the `thinkube-release` repository until they do.
* The full list of MCP operations is what Claude Code reads at `/mcp`; the site explains the ones a developer says, on xref:apps/claude-code.adoc[What Claude can do for you].

== Adding a page

. Decide the type and copy its skeleton from xref:contributing/page-types.adoc[Page types].
. Put it in the repository of the product it describes; only the site's own pages go in `thinkube.org`.
. Add it to `modules/ROOT/nav.adoc` in `thinkube.org`, once, under its section.
. Run the TL;DR on the reference cluster as written. Check every fact against source and name the file in the commit.
. Build with `npx --no-install antora --fetch antora-playbook.yml`; the build must print no warnings.
