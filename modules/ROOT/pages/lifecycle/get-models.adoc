= Get a model
:page-type: how-to

_Find a model that fits your hardware, mirror it into your registry, and know where it went._

.TL;DR
Ask Claude: "which models fit my GPU?" then "mirror Qwen/Qwen3-8B". The catalogue knows what each model needs, so the answer is computed from your hardware; the mirror runs as a job into your own registry, once. Ask for its status whenever you like.

== Why this is one sentence

Every model in the catalogue carries the facts serving needs, its size, quantization, context length, backends and stop tokens, so the platform can say what fits and configure the server from the entry instead of from a guess. That is the decision behind the single sentence: the catalogue is the source of truth, and the registry keeps the weights once, on your storage.

Models come from Hugging Face by way of the catalogue. You never download one
straight onto a node: you mirror it once, it lands in Thinkube Storage, it is
registered in Thinkube Experiments, and it is served from there. In
thinkube-control this is *AI Models*.

image::cp-model-catalog.png[The AI Models page of thinkube-control: the catalogue, with mirror controls]

== Find one that fits

----
› which models in the catalogue fit my GPU?
----

The catalogue carries what each model needs — parameters, quantisation,
context length, which backends can serve it, its stop tokens — so the answer
is computed from your hardware, not guessed. For one model:

----
› would Qwen3-14B fit, and on which backend?
----

Claude reads the load options: compatible backends, GPU nodes with room,
estimated memory, context length.

== Mirror it

----
› mirror Qwen/Qwen3-8B
----

The download runs as a job. Ask for its status and Claude reads it. When it
finishes, the model shows as mirrored in the catalogue and can be loaded.

== Gated models

Some models on Hugging Face require you to accept a licence first. Accept it
there, and make sure the token you gave the installer has access —
xref:install:huggingface-token.adoc[Unlock AI models]. Without access, the
mirror job fails.

== A model that isn't in the catalogue

The catalogue is a file — `models.json` in `thinkube-metadata` — with one
entry per model: id, parameters, quantisation, context length, backends, stop
tokens, licence. A model that isn't there needs an entry before it can be
mirrored, because the entry is what tells the gateway how to serve it
correctly.

== Where it lives

The weights are in Thinkube Storage. The registry entry — version, the run
that produced it if you made it, metadata — is in Thinkube Experiments.
Serving reads from those, and never from Hugging Face again.

== Limits

* A model that is not in the catalogue needs an entry before it can be mirrored; the entry is what tells the gateway how to serve it.
* A gated model needs its licence accepted on Hugging Face with the account your token belongs to.
