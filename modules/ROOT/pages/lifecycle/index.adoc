= Thinkube Models
:page-type: concept

_Open models on your own GPUs: get one, serve it at one address, work with it in notebooks, fine-tune it and serve the result the same way. What that rests on, what it saves you, and where each part is explained._

.TL;DR
Ask Claude: "get Qwen/Qwen3-8B and load it on the spark". The model is mirrored once into your registry and served at `llm.<your domain>` through the OpenAI or Anthropic API. Write your app or your notebook against that address. When the prompt is not enough, fine-tune the model in a notebook, register the result, and load it at the same address.

== The decision

A model you own and can change beats a model you rent and cannot. So Thinkube serves open models only, keeps them in your own registry, and gives every one of them the same address and API through the LLM Gateway. The catalogue carries what each model needs to run, so the platform can say what fits your GPU before you download anything and configure the server from the entry rather than from a guess. xref:why/index.adoc[Why Thinkube] makes the case; xref:concepts/models.adoc[Concepts: models] explains the words.

Nothing in this area is its own infrastructure. The weights live on Thinkube Storage, the runs and registered models in Thinkube Experiments, the notebooks on the same filesystem as Thinkube IDE and the apps of Thinkube GitOps, and every GPU is counted by the base. A dataset a notebook writes is a file an app can read, and a model a notebook registers is served at the address the app already calls.

== What it saves you

* *One download, ever.* A model is mirrored once from Hugging Face into Thinkube Registry and served from your storage from then on.
* *One address, every model.* Your code speaks to `llm.<your domain>`; the model behind it changes without the code changing.
* *No sizing by hand.* The platform computes what fits from the catalogue and your GPU budget, and refuses a load that will not fit.
* *No environment to build.* Notebooks open with kernels built for your hardware, and `tk_llm` already knows the gateway.
* *No bill per experiment.* Once the hardware is yours, trying a model, comparing two, or fine-tuning costs nothing extra.

== Limits

* Every served model needs a catalogue entry; a model that is not in the catalogue needs one added first.
* A backend serves one model per node at a time.
* The inference servers are optional components, `vllm`, `tensorrt` and `text-embeddings`; a model loads only on a backend that is installed.
