= Serve a model
:page-type: how-to

_Load a mirrored model onto a GPU, call it, and unload it when you're done._

In thinkube-control this is *LLM Gateway*.

== Load it

----
› load Qwen/Qwen3-8B
----

The LLM Gateway picks a backend and a node and loads the model. It reports
`loading`, then `available`.

== Choose how it loads

Loading takes options. Say them in words, or set them in thinkube-control:

* *tier* — `flexible` loads through Ollama when the model supports it:
  quantised, quick to load, less memory. `performance` loads through vLLM or
  TensorRT-LLM: full precision, higher throughput.
* *backend* — name one: `vllm`, `tensorrt-llm`, `ollama`, `text-embeddings`.
* *node* — which GPU node. The gateway chooses if you don't.
* *max_context_length* — cap the context to save memory.
* *keep_alive* — Ollama only: how long the model stays loaded after the last
  request.
* *num_speculative_tokens* — for models with a speculative-decoding
  configuration, the draft depth.

----
› load Qwen3-8B on the spark with a 16k context
----

== See what's loaded

----
› what's on the GPUs?
----

Claude reads the GPU status: each node's slots, what holds them, memory used.
On a DGX Spark it also shows the AI budget and the reserve.

== Call it

Every loaded model sits behind one endpoint at `llm.<your domain>`, which
speaks both the OpenAI API and the Anthropic Messages API. From a notebook:

[source,python]
----
from tk_llm import get_openai_client

client = get_openai_client()
response = client.chat.completions.create(
    model="Qwen/Qwen3-8B",
    messages=[{"role": "user", "content": "Hello"}],
)
----

From anywhere else, any OpenAI client pointed at the gateway with a token
from thinkube-control under *API Tokens*.

== Unload it

----
› unload Qwen/Qwen3-8B
----

The slot and the memory come back. Loading it again is fast: the weights are
already in Thinkube Storage.
