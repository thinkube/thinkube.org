= The example notebooks
:page-type: reference

_The five notebooks every notebook server starts with: what each one does, the environment and services it needs, what it leaves behind, and how to take a newer copy._

.TL;DR
Ask Claude: "which notebooks do I have?". Claude calls `jupyter_list_notebooks` and lists, among your own, `examples/research-assistant/` with four notebooks, `00` to `03`, and `examples/zebra-grpo/zebra_grpo.ipynb`. Then "run 00-platform-validation with agent-dev" checks every service the others use. The two playbooks walk the notebooks through step by step; this page is the map.

== Why they are there

A platform is easiest to believe when something runs on it. The notebooks use the same services your own work will use, the LLM Gateway, Qdrant, Langfuse, Thinkube Experiments, PostgreSQL, Valkey and NATS, and they keep the outputs of a real run, so you can read what should happen before you run them.

== The notebooks

[cols="2,1,2,3",options="header"]
|===
| Notebook | Kernel | Needs | Leaves behind

| `research-assistant/00-platform-validation.ipynb`
| `agent-dev`
| Nothing installed beyond the base; a service that is not installed is reported as skipped
| One line per service: reached, skipped, or failed with the error. A test run in Thinkube Experiments.

| `research-assistant/01-register-litellm.ipynb`
| `agent-dev`
| A chat model and an embedding model in the catalogue, mirrored
| Both models loaded at the LLM Gateway, for 02 and 03 to call.

| `research-assistant/02-langchain-rag.ipynb`
| `agent-dev`
| Qdrant, Langfuse, outbound access to arXiv, the models 01 loaded
| The Qdrant collection `rl_reasoning_papers`, answers with their sources, and the traces in Langfuse.

| `research-assistant/03-multi-agent.ipynb`
| `agent-dev`
| The collection from 02, a chat model the catalogue marks for tool use, Langfuse
| A debate between two agents that can cite only what the search returns, and a judge's verdict.

| `zebra-grpo/zebra_grpo.ipynb`
| `fine-tuning`
| A GPU node with about 20 GB of GPU memory free, `unsloth/Qwen3.5-4B` mirrored, the vLLM backend installed
| The experiment `zebra-grpo` in Thinkube Experiments, the registered model `zebra-rules-qwen35-4b`, served at the gateway.
|===

Run the research assistant in order: each notebook uses what the one before it left. The zebra notebook stands alone. Install Qdrant and Langfuse before `02`; ask Claude "install Qdrant and Langfuse".

xref:playbooks/research-assistant.adoc[Build a research assistant, end to end] and xref:playbooks/zebra-grpo.adoc[Fine-tune on verifiable rewards, end to end] follow them one step at a time and show what each step printed on the reference cluster.

| The source
| https://github.com/thinkube/thinkube-notebooks-examples[thinkube-notebooks-examples] on GitHub

The copy in `notebooks/examples/` is yours. It is made the first time a notebook server starts and never touched again, so your edits and outputs stay.

== Take a newer version

Every time a notebook server starts, a fresh clone of the repository is placed in `thinkube/templates/examples/`, visible in the file browser of Thinkube Notebooks. To take a newer notebook, copy it from there over your own, or next to it under another name to compare. Nothing is overwritten for you.

== Run them from Claude

Claude opens a notebook with a kernel, runs it cell by cell or whole in the background, and reads the outputs, without a tab open:

----
› start a notebook server on tkamd1
› run examples/research-assistant/00-platform-validation.ipynb with agent-dev
› run the zebra notebook unattended on the spark with one GPU
----

The research assistant needs no GPU in the notebook server: the models run behind the gateway. The zebra notebook needs the GPU in the server itself. xref:control:notebooks.adoc[Notebook execution over MCP] lists the operations.

== Limits

* The notebooks are written against the environments as built at install. An environment rebuilt with other package versions can break an import.
* `02` fetches papers from arXiv; without outbound access it has nothing to index.
* The zebra notebook's full scale trains for a long time on one GPU; its `FULL_RUN` flag switches to a small scale that runs every stage the same way.
