= Thinkube GitOps
:page-type: concept

_Push to git, and it runs: an application goes from a template to an address with a certificate and a login, and every change after that is a push. What that rests on, what it saves you, and where each part is explained._

.TL;DR
Ask Claude: "make an app called notes from the web app template". A repository named `notes` appears in Thinkube Git, is built, deployed and given `notes.<your domain>` behind your login, with a PostgreSQL database of its own, and is checked out under `apps/notes` in your workspace. Edit it and push; the push builds and deploys. That is the whole build story; the pages below are its parts.

== The decision

Production is a system, not a script. An application needs an address with a certificate, a login, a build that repeats, a rollback, a database, and a way to reach a model, and all of that already exists on the base. So Thinkube does not ask you to describe any of it. You describe the application in about twenty lines of `thinkube.yaml`, containers, ports, routes, services, and the platform generates the Kubernetes manifests, builds the images, deploys them, and puts the login and the certificate in front.

The repository is the only source of truth. The generated manifests are committed beside your code, a push builds the images, and the cluster runs what the repository says, so what is running is always a commit you can read, and rolling back is checking out the previous one.

A template is an application that already runs, which you copy and change; what you publish back is a template again.

== What it saves you

* *No manifests.* `k8s/` is generated from `thinkube.yaml`; you read it, you never write it.
* *No pipeline to build.* A push builds and deploys. Ask Claude for the status, or watch it under *Templates* in thinkube-control.
* *No plumbing to the model.* The app calls the LLM Gateway with a token; the model behind it can change without the app changing.
* *No lock-in.* What comes out is a git repository with real code, tests and a standard image. It builds and deploys anywhere Kubernetes runs.

== Limits

* The web app template is React and FastAPI with PostgreSQL; other stacks are templates you write or publish yourself.
* Login on a deployed app is the platform's; it is not automatic at the route, the app asks for it.
